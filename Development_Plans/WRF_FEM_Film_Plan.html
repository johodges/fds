Fire Dynamics Simulator · development plan

WRF two-way coupling, FEM solid heat transfer, and a surface liquid-film solver

What FDS does today, and a phased plan for three new capabilities. The first is two-way coupling with the WRF weather model, in the spirit of WRF-SFIRE. The second is a finite-element solver for complex 3-D conduction in solids. The third is a FireFOAM-style thin-film model for water flowing over surfaces.

Summary

At a glance

Once a small set of shared foundations is in place, the three tracks are independent of each other. Effort figures are rough person-month ranges for an experienced FDS developer. Refine them after Phase 0.

Track A

Two-way coupling with WRF

14–20 pm FDS + 3–5 pm WRF
Approach

FDS runs as a fine-scale LES nest inside WRF. WRF supplies time-varying boundary and initial fields. FDS returns the fire's heat, water vapour and smoke on WRF's grid, injected through WRF-Fire's tendency code (the SFIRE analogue). Offline one-way first, then online two-way.

Reuses
  • OPEN boundaries and DFSEM
  • PATCH_VELOCITY_FLUX forcing pattern
  • CSVF initial fields
  • UPDATE_HRR integrals
  • External-control heartbeat
  • Unused ORIGIN_LAT/LON, NORTH_BEARING
Obstacles
  • Wind is one U(z) profile per mesh
  • Inflow T and humidity are uniform
  • MPI_COMM_WORLD hard-coded 307 times
  • No geolocation or projection
  • DT is not clipped to exchange times
Track B

FEM solid heat transfer

18–28 pm
Approach

An unstructured 3-D conduction and pyrolysis solver that replaces HT3D. It uses linear tetrahedra with a lumped mass matrix (equivalent to vertex-centred finite volumes), implicit time stepping, and HYPRE PCG/AMG. The 1-D solver stays the default for ordinary surfaces.

Reuses
  • Tetrahedra already stored in GEOMETRY%VOLUS
  • .bingeom, BOX2TETRA
  • PROC_MATL tables, PYROLYSIS kinetics
  • HYPRE_INTERFACE
  • HT3D verification suite, including an ANSYS I-beam benchmark
Obstacles
  • HT3D is direction-split 1-D lines with replicated state
  • Face-centric data, Cartesian IOR assumptions
  • PYROLYSIS reads gas arrays directly
  • Solid partition tied to gas meshes
Track C

Surface liquid film

14–22 pm
Approach

Depth-averaged film mass, momentum and energy, solved on a dedicated surface mesh: wall-cell quads for OBSTs and GEOM triangles for complex shapes. The film is an extra implicit node in the solid's surface heat balance. It couples to sprays (absorb, drip, separate, splash) and to the gas through the wall mass-flux path.

Reuses
  • Surface-droplet hooks in MOVE_PARTICLES
  • Droplet evaporation correlations
  • Wall-function mass transfer from condensation
  • CALCULATE_ZZ_F mass-flux path
  • EDGE_FACES triangle adjacency
Obstacles
  • No wall-cell connectivity
  • CFACEs have no adjacency
  • Mixed WALL and CFACE surfaces
  • Droplet–wall coupling is explicit and lagged
Phase 0

Shared foundations

3–5 pm

An FDS MPI communicator, a surface-mesh layer, a sparse-solver wrapper, and an explicit solid–gas exchange contract. Each is small, and together they unblock all three tracks.

Recommended order

  1. Phase 0 first. It is small and unblocks all three tracks.
  2. Then run the tracks in parallel. A1 (offline WRF → FDS) and B1 (serial FEM conduction) deliver results earliest.
  3. Film work starts on Cartesian walls over 1-D solids. It moves onto FEM solid surfaces once B5 lands.
Phase 0

Shared foundations

0.1 An FDS communicator

Today. MPI_COMM_WORLD appears 307 times in 11 files: main 152, ccib 74, pres 26, geom 26, dump 7, fire 6, hvac 5, read 4, func 3, turb 2 and radi 2. FDS also owns MPI start-up and shut-down:

  • MPI_INIT_THREAD at main.f90:89.
  • MPI_FINALIZE then STOP in END_FDS (main.f90:1794-1869).
  • MPI_ABORT on WORLD at main.f90:3987 and ccib.f90:5124.

Several communicators are derived from WORLD: MPI_COMM_NEIGHBORS (main.f90:1238-1260) and ZSL_COMM (pres.f90:4470). The MKL cluster solver is handed WORLD directly (pres.f90:3361 ff.).

Change.

  • Add TYPE(MPI_COMM) :: MPI_COMM_FDS next to MPI_COMM_NEIGHBORS (cons.f90:389). Standalone it is WORLD; coupled, it is FDS's colour of an MPI_COMM_SPLIT.
  • Take MY_RANK and N_MPI_PROCESSES from it, and replace every use of WORLD. This is mechanical because the code uses MPI_F08.
  • Skip MPI_INIT when MPI_INITIALIZED is already true, and let the coupler finalize in coupled mode.

Acceptance. The whole verification suite is bit-identical. Needed by A2 (MPMD with WRF), plus B3 and C3 (sub-communicators for solid and film ranks).

0.2 Surface-mesh layer

A new module (for example smsh.f90) that holds a conformal polygonal surface mesh with edge adjacency. It is independent of the gas grid and carries conservative maps to the gas-side boundary faces.

  • Facets store area, unit normal, centroid, vertices and owner mesh or rank. Edges store two facets, fold angle and edge vector.
  • Maps from each facet to WALL(IW) or CFACE(ICF), with area weights.
  • Halo exchange through a new MESH_EXCHANGE code with persistent requests. Model it on codes 66 and 67 (main.f90:3341-3372, 3726-3760) and INITIALIZE_BACK_WALL_EXCHANGE (main.f90:2204-2460).
  • Static in v1. Stop with an error if a filmed or FEM surface belongs to a removable OBST. Dynamic rebuild later hooks into REASSIGN_WALL_CELLS (init.f90:4909).

Builders

  1. Cartesian OBST surfaces. One quad per solid WALL cell. Neighbours across the four edges are derived from CELL%WALL_INDEX(-3:3) (type.f90:2174-2186), as the figure shows. Cross-mesh neighbours use FIND_WALL_INDEX (func.f90:5501) and the remote CELL data from EXCHANGE_GEOMETRY_INFO (func.f90:5377).
  2. GEOM surfaces. Use GEOMETRY%FACES with FACE_EDGES and EDGE_FACES (type.f90:1191, built by GET_GEOM_EDGES at geom.f90:946). Closed manifold geometry is already enforced (geom.f90:876-893), so every edge has two triangles. Add optional refinement to about one gas cell. Map facets to CFACEs through CUT_FACE%BODTRI (type.f90:1305) with area weights; the map is many-to-many because cut cells can be merged or blocked.
  3. FEM boundary triangles from Track B.

0.3 Sparse linear-solver wrapper

  • Generalize HYPRE_INTERFACE (imkl.f90:200-543) into a small API:
    • IJ assembly, including off-process entries.
    • PCG for SPD systems and GMRES for others.
    • BoomerAMG with setup reuse.
    • A communicator argument.
    • Runtime tolerances and iteration limits. Today these are compile-time PARAMETERs at imkl.f90:204-229.
  • Keep PARDISO (imkl.f90:7-96) as an optional single-rank direct solver.

  • HYPRE is already fetched by default in CMakeLists.txt (USE_HYPRE is ON), so this adds no new dependency.

0.5 Ground rules for all tracks

  • Opt-in only. Every feature is off by default, and default inputs give bit-identical results (Firebot regression).

Track A

Two-way coupling with WRF

The wind FDS imposes today is a single vertical profile per mesh, the same everywhere horizontally. The plan replaces it with spatially and temporally varying WRF boundary data, and returns the fire's sources to WRF.

Architecture

FDS becomes a nest inside WRF's innermost domain. WRF values are interpolated onto FDS boundary faces with precomputed weights. The fire's sources go back to every WRF cell the FDS domain overlaps, weighted by the overlap.

Key design decisions

  1. FDS is a nest, not an embedded fire module

    WRF-SFIRE embeds a semi-empirical level-set spread model on a refined fire grid inside WRF. Because WRF has no flux boundary conditions, the fire's sensible and latent heat is inserted as forcing over a layer above the surface, with an assumed exponential decay in height (Mandel et al. 2011). FDS's value is its resolved fire and plume physics, so FDS should receive WRF boundary data and return sources.

    An SFIRE-equivalent mode is still worth building as a stepping stone (A2a). In it, LEVEL_SET_MODE=1 is driven by WRF winds and returns surface fluxes. That isolates the coupling infrastructure from LES issues, and the result can be compared directly with WRF-SFIRE.

  2. What WRF sends

    • u, v, w, converted from grid-relative to earth-relative and then rotated into FDS axes.
    • T, computed from θ (θm in WRF v4) and p = P + PB.
    • YH2O = qv/(1 + qv).
    • PBL diagnostics (u*, TKE or PBL height, surface heat flux) for the inflow turbulence generator.
    • Surface pressure.

    These are sent on the FDS lateral and top boundary points and on relaxation-zone cells. Full 3-D initial fields are sent once.

  3. What FDS returns: feedback mode SOURCES (default)

    For every WRF cell that overlaps the FDS domain, FDS returns interval-averaged values of:

    • Sensible heating. This is the sum of (q‴ + QR)·dV over the FDS gas cells, plus wall convective heat to the gas (−Q_CON_F·A), minus droplet-evaporation sinks. WRF applies it as a θ tendency.
    • Water vapour from combustion, fuel moisture and suppression water, applied as a qv tendency.
    • Smoke and soot, plus optionally CO and CO2 for WRF-Chem, applied as tracer tendencies.

    This generalizes SFIRE's assumed exponential profile with FDS's resolved 3-D distribution. WRF still carries the plume beyond the FDS box. The fire-induced far-field indraft then comes back through the FDS lateral boundaries, which closes the two-way loop.

    A 2-D variant sends column integrals only. These map directly onto WRF-Fire's ground and canopy heat and moisture flux arrays, so a first version can reuse WRF-Fire's injection code unchanged.

    A later, optional mode, STATE, relaxes WRF fields in the overlap toward box-filtered FDS fields, as WRF's own nest feedback does. It is mutually exclusive with SOURCES to avoid double counting.

  4. Coordinates and geolocation

    • Give ORIGIN_LAT, ORIGIN_LON and NORTH_BEARING real meaning, and add ORIGIN_ELEVATION for the vertical datum.
    • The preprocessor maps WRF projection coordinates (Lambert, Mercator, polar stereographic, lat-lon) to local x, y.
    • Winds are rotated from grid-relative to earth-relative (WRF COSALPHA/SINALPHA) and then to FDS axes (NORTH_BEARING).
    • All weights are stored in a SCRIP-style file, so FDS only does sparse dot-products at runtime.

  5. Vertical interpolation and terrain mismatch

    WRF heights come from (PH + PHB)/g on w-levels, and WRF terrain (HGT) is much smoother than the FDS DEM.

    • Interpolate in height above ground at each boundary column.
    • Offer a terrain-blending strip along the lateral boundaries, applied in preprocessing next to qgis2fds.
    • For FDS points below WRF's lowest level, extrapolate with a Monin–Obukhov profile from WRF's u* and L.

  6. Thermodynamics

    • Set P_INF and TMP_0(z) from the WRF footprint-mean column at start-up, using the existing RAMP_TMP0_Z route.
    • Hold the background frozen in v1. This is a documented limitation for multi-hour runs. A time-varying P0 needs the dp̄/dt term in the divergence.
    • Variable humidity needs an explicitly tracked WATER VAPOR species over a dry-AIR background, because HUMIDITY is folded into AIR today.

  7. FDS boundary conditions

    Replace the 1-D U_WIND(K) with per-external-wall-cell targets at two time levels (U_BC, V_BC, W_BC, TMP_BC, ZZ_BC(:)), interpolated linearly in time.

    Keep the existing OPEN formulation, applied per face: Dirichlet H for normal velocity, ghost-cell tangential velocity, and upwind selection of T and Y. If the soft coupling drifts in strong cross-flow, evaluate a specified-normal-velocity inflow with a global mass-flux correction, as PALM's offline nesting does.

  8. Inflow turbulence

    Mesoscale WRF fields carry no resolved turbulence. There are two options:

    • DFSEM with per-face statistics scaled from WRF PBL diagnostics. Today it uses one mean wind and one intensity (turb.f90:1726-1738, 2021-2023).
    • The stochastic cell-perturbation method (Muñoz-Esparza et al.) applied to θ in a boundary strip. It is cheap and widely used for WRF → LES nesting.

    When the parent is WRF-LES, the fluctuations are resolved, and the exchange interval should be no longer than the WRF time step.

  9. Lateral relaxation zone (optional)

    A Davies-type relaxation of velocity toward WRF over N cells inside the boundary. Implement it like PATCH_VELOCITY_FLUX and call it next to DIRECT_FORCE (velo.f90:839-841). It absorbs plume-induced reflections. It covers velocity only in v1, because scalar relaxation would have to pass through the divergence and the species sources.

  10. Time synchronization

    Sequential, staggered and explicit, as in the timeline above. Before ignition, spin FDS turbulence up for 10–30 minutes with feedback off.

    for each coupling interval [t_n, t_n+1]   (Δc = integer × WRF dt):
    WRF advances t_n → t_n+1 using FDS sources averaged over [t_n-1, t_n]
    WRF → FDS: boundary state at t_n+1
    FDS advances t_n → t_n+1, BCs interpolated in time, DT clipped to land on t_n+1
    FDS → WRF: sources accumulated over [t_n, t_n+1]

  11. Coupler backends

    An abstract cplr.f90 API: CPL_INIT, CPL_RECV_BOUNDARY, CPL_SEND_SOURCES, CPL_FINALIZE. It has three backends:

    • OFFLINE: pre-generated boundary files, one-way.
    • OASIS3-MCT: parallel regridding with precomputed weights and MPMD launch. WRF contains an OASIS3-MCT interface for ocean coupling (frame/module_cpl*.F in recent releases); confirm this for the target version.
    • Plain MPI intercommunicator: the fallback.

    preCICE and ESMF/NUOPC are alternatives, but they are heavier for 3-D volume data.

WRF-side work (in a WRF fork)

  • Registry. Namelist options (for example fds_coupling, fds_coupling_interval and a feedback mode) and state arrays for the received sources.
  • Communicator. Run WRF on its colour of the split. WRF's DM layer accepts an externally supplied communicator, which is how MPMD-coupled systems such as COAWST run it. Confirm the mechanism for the target version.
  • Send. At each coupling time, sample WRF fields on FDS boundary points; the coupler gathers them from the WRF tiles.
  • Receive. Add the FDS sources as θ, qv and tracer tendencies, reusing WRF-Fire's fire-tendency arrays with its own spread model switched off.
    • For the 2-D variant, fill WRF-Fire's ground and canopy flux arrays and keep its fire_ext_grnd/fire_ext_crwn extinction-depth distribution.
    • The array names differ between NCAR WRF (WRF-Fire in phys/module_fr_fire_*.F) and OpenWFM WRF-SFIRE. Pick the target first.
  • Restart. Align WRF and FDS restart times.

A3

Validation and hardening

3–4 pm

Verification and validation

  • Verification.
    • Weights reproduce constant and linear fields exactly.
    • Binned sources conserve totals.
    • A restart reproduces a continuous run.
    • Results are invariant to the FDS MPI process count.
  • Regression. The existing &WIND profiles, fed through the new file path, reproduce Verification/Atmospheric_Effects/* and Verification/Turbulence/sem_open_wind*.
  • Flow validation. Validation/Askervein_Hill driven by WRF instead of M-O inflow, and Validation/Schoenberg_Ekman_Layers compared against WRF-LES.
  • Coupled fire. FireFlux, and Validation/CSIRO_Grassland_Fires cases with WRF-supplied winds.

Track B

FEM solid-phase heat transfer

Recommendation: replace HT3D, keep the 1-D solver

Recommendation

Replace HT3D and the VARIABLE_THICKNESS path with an unstructured 3-D solver. Keep the 1-D solver as the default wherever 1-D conduction is adequate.

The 1-D solver is fast and embarrassingly parallel. It also carries validated physics with no 3-D counterpart: liquid-fuel B-number evaporation, SPyro, TGA, shrink/swell remeshing and thermally thick particles. Most of the Validation suite rests on it. A 1-D column is a degenerate FEM mesh, so replacing it gains nothing and puts every pyrolysis validation case at risk.

Existing HT3D inputs (SURF HT3D=T plus OBST MATL_ID) run unchanged on the new solver. Keep the legacy HT3D behind MISC HT3D_SOLVER='LEGACY' until the FEM matches it on the full HT3D verification suite.

Numerical formulation

Heat equation in each solid region

ρc(T) ∂T/∂t = ∇·(k(T) ∇T) + q̇‴

q̇‴ is the sum of reaction heat, the user internal source (HEAT_SOURCE with its ramp) and, later, absorbed in-depth radiation. k is a scalar or a symmetric tensor per element. Anisotropy, such as wood grain or laminates, is a new capability; HT3D has none.

Space discretization

  • Continuous P1 Galerkin on tetrahedra with a lumped (diagonal) mass matrix. For P1 simplices, the Galerkin stiffness matrix equals the vertex-centred median-dual finite-volume (CVFEM) diffusion operator. So this choice is also the conservative finite-volume "equivalent". Nodal unknowns carry dual-cell volumes, which gives local mass and energy conservation for pyrolysis bookkeeping.
  • Mesh quality. With lumped mass, the discrete maximum principle needs non-obtuse tetrahedra. An orthoscheme (Kuhn) split of the graded box grid used for OBSTs gives non-obtuse tetrahedra. For imported GEOM meshes, quality checks warn on obtuse dihedral angles.

Time integration (θ-scheme)

(ML/Δt + θA) Tn+1 = (ML/Δt − (1−θ)A) Tn + F

The default is θ = 1 (backward Euler), which is L-stable and does not oscillate at large Fourier numbers. Crank–Nicolson is an option for one-to-one comparison with the 1-D solver, and BDF2 comes later.

Surface boundary condition (Robin, per boundary facet)

−k∇T·n = h(T − Tg) + εσT4 − qrad,in − qliquid, εσT4 ≈ εσ(4T*3T − 3T*4)
  • The radiation linearization is the same trick the 1-D solver uses, and h, Tg and qrad,in are lagged as in 1-D.
  • Dirichlet (TMP_FRONT) and insulated options are supported.
  • Facets on exterior boundaries use the SURF backing condition, which removes HT3D limitation 1.

Nonlinearity and the linear solve

  • Picard iteration (1–3 sweeps with a convergence test) on k(T) and ρc(T) from the PROC_MATL tables. Interpolate between table entries; the 1-D solver truncates to INT(T).
  • An enthalpy-consistent update keeps energy conserved with T-dependent cp and reactions. The ht3d_energy_conservation* cases are the gate.
  • The linear system is SPD: the Robin and mass terms are symmetric and the coefficients are lagged. Solve it with PCG + BoomerAMG through the Phase 0.3 wrapper, reusing the AMG setup while coefficients change slowly.

Pyrolysis and mass transport in 3-D

  • Kinetics at nodes. Nodal (dual-volume) component densities ρi. Rates come from the refactored pure kinetics routine: A, E, ns, nT, nO2, NU_* and HR(T).
  • Gas routing. The 1-D model releases gas instantly at its own face. In 3-D, each node's gas production goes to its nearest exposed facet, using a precomputed graph-distance field (Dijkstra from the boundary nodes) and the same instant-release assumption.
    • This replaces the LAYER_DIVIDE and HT3D_WEIGHT heuristics. Document the semantic change.
    • Darcy flow in porous char is a later option.
  • In-depth oxygen. XO2 at a node is XO2 at its routed facet × exp(−d/GAS_DIFFUSION_DEPTH). This generalizes wall.f90:3471-3491.
  • Geometry change.
    • v1 has none: density falls at fixed volume, as in HT3D today.
    • B6 adds element deactivation. When all elements in a gas cell are consumed, that cell is removed through the existing BURN_AWAY and REASSIGN_WALL_CELLS machinery (init.f90:4909).
    • GEOM burn-away stays out of scope, because cut-cell geometry is static.
  • Stays 1-D: liquid fuels, thermally thick particles, SPyro and TGA.

Parallelization

  • Ownership. Elements belong to the rank that owns the gas mesh containing their centroid. Interface facets therefore sit with their WALL or CFACE owners, and interface data needs no extra communication. Shared nodes become ghost nodes.
  • Assembly. Element-by-element into HYPRE IJ, with off-process contributions handled at assemble time, and contiguous per-rank offsets as in GET_MATRIX_INDEXES_H.
  • Load balance. Geometric ownership can be unbalanced when solids dominate. Add optional graph partitioning (ParMETIS, or recursive coordinate bisection to avoid a dependency) with a facet-data redistribution step.
  • Invariance. Results are tested to be independent of the MPI process count, to solver tolerance.

Governing equations

The equations are depth-averaged over the film thickness δ, on each facet with unit normal n pointing into the gas. U is the tangential film velocity.

Mass

∂(ρlδ)/∂t + ∇s·(ρlδU) = ṁ″imp − ṁ″evap − ṁ″drip/sep + ṁ″src

Momentum

∂(ρlδU)/∂t + ∇s·(ρlδUU) = −δ∇spf + ρlδgt + τg − τw + Simp
pf = −ρl(g·n)δ − σ∇s2δ, τw = 3μlU/δ
  • Film pressure. On a floor, g·n = −g, so the pressure is hydrostatic and drives spreading. On a ceiling the sign reverses, and the Rayleigh–Taylor-unstable film drips (C4).
  • Wall shear assumes a laminar, half-parabolic velocity profile.
  • Gas shear comes from the wall model's uτ and the gas tangential velocity (B2%U_TAU, B1%U_TANG). WALL_MODEL must be called whenever a film is active. Today it runs only for condensation, deposition or wall outputs (wall.f90:163-167).

Energy (single film temperature)

∂(ρlδhl)/∂t + ∇s·(ρlδUhl) = q″w + q″g + q″rad,abs − q″rad,emit − ṁ″evaphfg + ṁ″imphimp − ṁ″outhl
  • Wall-to-film conductance: hfw ≈ 2kl/δ.
  • Gas side: the existing HEAT_TRANSFER_COEFFICIENT.
  • Evaporation: a Spalding B-number and Sherwood formulation. It reuses GET_FILM_PROPERTIES and FORCED_CONVECTION_MODEL (func.f90:2862, 3368), or the wall-function mass transfer from CONDENSATION_EVAPORATION (fire.f90:2153-2220).
  • Wetted fraction fw ∈ [0, 1] comes from δ relative to a critical thickness. That thickness is user-set, or derived from a contact angle and a minimum wetting rate. Fluxes split into a wet path through the film and a dry path from the gas straight to the solid.

Discretization

  • Control volumes. Cell-centred finite volumes on the Phase 0.2 surface mesh, one per facet. The unknowns per facet are ρlδ; the momentum ρlδU, stored as a 3-D vector projected onto the facet plane; and Tf.
  • Fluxes across shared edges. TVD upwind for advection, using FDS's existing limiters. Green–Gauss gradients for pf. An edge-based Laplacian for ∇s²δ.
  • Folded edges. Where a flux crosses an edge between facets with different normals (90° Cartesian edges or GEOM creases), the transported momentum is rotated about the shared edge (Rodrigues rotation). Water flowing over a convex edge then continues down the next face, unless the separation criterion sheds it.
  • Positivity. Edge outflow is limited to the available mass. Dry facets have δ = 0 and U = 0.
  • Time stepping. Advection is explicit and sub-cycled to a film CFL on Δx/(|U| + √(gδ)). Wall friction and source terms are point-implicit.
  • Placement in the corrector. After PARTICLE_MASS_ENERGY_TRANSFER, MOVE_PARTICLES and the particle exchange (main.f90:888-905), and before WALL_BC (main.f90:911).
  • Staircases. On Cartesian staircase surfaces, the effective slope emerges from flow over treads and risers, driven by hydrostatic spreading on the treads. GEOM gives true slopes.

Coupling

  1. Solid: the film as an implicit node

    • The 1-D solver gains one lumped node in front of the surface node. It has capacity ρlclδ and conductance fwhfw to the surface, with gas, radiation and evaporation fluxes on its top side. It fits the existing ghost-node Robin formulation (RFACF/QDXKF, wall.f90:2867-2880).
    • Wetted surfaces use WALL_INCREMENT=1, as SURFACE_OXIDATION_MODEL already forces (read.f90:7310).
    • The film solver transports film enthalpy between facets. The solid solver owns the wall–film exchange and writes the updated Tf back. Both use the same integrated flux, so energy is conserved exactly.
    • On filmed surfaces this replaces the explicit LP_CPUA path. Surfaces without a film are unchanged.

  2. Gas

    Evaporated water enters the gas as a surface mass flux of WATER VAPOR, through the existing M_DOT_G_PP_ADJUST → CALCULATE_ZZ_F path (wall.f90:1036-1461). That gives the blowing velocity and ZZ_F consistently, exactly as pyrolysate does.

    On wetted area, the surface temperature and emissivity seen by convection and radiation (TMP_F, EMISSIVITY → radi.f90:4220-4250) are the fw-weighted film and solid values.

  3. Lagrangian droplets

    • Impingement. When a droplet reaches a filmed surface, its mass PWT·m, tangential momentum and enthalpy are deposited into the facet, and the particle is removed. The contact points are in MOVE_PARTICLES (part.f90:2438-2472), CFACE_SEARCH (part.f90:1996-2363) and VENT_PARTICLE_EXTRACTION (part.f90:3067). The Bai–Gosman stick/rebound/spread/splash map comes in C4.
    • Release.
      • Drips fall from downward-facing facets once δ exceeds a critical thickness. The drip size scales with the capillary length √(σ/ρg), using the existing DRIP_DIAMETER.
      • Separation at convex edges follows a force-ratio criterion.
      • Re-emitted droplets go through PARTICLE_FACE_INSERT (part.f90:603-944).
    • Surfaces without a film keep today's surface-droplet model.

  4. Suppression and sources

    • On MATL-pyrolysis surfaces, suppression follows physically from cooling through the film node.
    • E_COEFFICIENT can use film mass per area in place of the summed LP_MPUA, for continuity with existing inputs.
    • A new SURF FILM_MASS_FLUX (kg/m²/s), plus a line-source option at a top edge, models wetted walls, water curtains and run-down.

MPI

  • Ownership. A facet belongs to the rank that owns its WALL or CFACE. GEOM triangles that straddle meshes belong to the mesh containing the refined triangle's centroid.
  • Halos. δ, U and Tf of neighbour facets are exchanged with the new Phase 0.2 MESH_EXCHANGE code. Edge fluxes are computed identically on both sides from the same states, so they stay conservative.
  • Invariance. Results are tested to be invariant to the MPI process count, using cascadempi.fds as the template.

Before starting

Decisions needed

  1. WRF flavour and version. NCAR WRF v4.x (WRF-Fire in phys/) or OpenWFM WRF-SFIRE. This decides where the WRF-side hooks go and which flux arrays are reused.
  2. Coupler backend. OASIS3-MCT is recommended if the target WRF has its OASIS interface. The alternative is a bespoke MPI intercommunicator.
  3. Scope of "replace". Replace HT3D and keep the 1-D solver (recommended), or replace the 1-D solver as well. Replacing the 1-D solver too is not recommended.
  4. Element types. P1 tetrahedra only for v1 (recommended), or also Q1 hexahedra for OBSTs.
  5. Tooling dependencies. Python preprocessors in Utilities/ (wrf2fds with netCDF and pyproj; fds_tetmesh with gmsh) keep the FDS runtime free of dependencies beyond HYPRE and an optional OASIS3-MCT. Is that acceptable?
  6. Upstream intent. If the goal is to merge into firemodels/fds, engage the NIST developers early. This matters for the 2014 MEAN_FORCING/WRF history, HT3D ownership, and manual and Firebot conventions.
  7. Priority if resources are limited. Each track is independent after Phase 0.
Found along the way

Pre-existing issues

These turned up while mapping the code. They are outside the three features, but they affect them.

Bug

Droplet wall cooling is undercounted when the evaporation step sub-cycles

  • LP_CPUA accumulates Q_CON_WALL/DT (part.f90:4361-4362), but Q_CON_WALL is only the last sub-step's energy.
  • Q_CON_SUM is summed over all sub-steps (part.f90:4338) and never used.
  • The gas-phase energy budget (Q_DOT(5), part.f90:4322) counts every sub-step.

So the wall cooling and the energy budget disagree in hot-wall cases.

Doc mismatch

Documented minimum film thickness is not implemented

The Technical Reference Guide gives the droplet film thickness as δ = max(δmin = 10−5 m, …) (Particle_Chapter.tex, "Droplet Transport on a Surface"). The code uses a footprint-coverage test instead (part.f90:3774, 3781).

Doc mismatch

Outdated Verification Guide note on HT3D

It says HT3D "is not yet connected to the 1-D pyrolysis" (FDS_Verification_Guide.tex:4868). But ht3d_mass_conservation.fds exercises HT3D with pyrolysis.

Dead branch

LEVEL_SET_MODE=5 is undocumented, and its prescribed-wind branch never takes effect

  • Mode 5 sets LEVEL_SET_COUPLED_WIND=.TRUE. (read.f90:2012).
  • Its prescribed-wind branch (vege.f90:356-365) is then overwritten by the CFD sampling block (vege.f90:371-402).

This is relevant to A2a, which needs a fire-coupled mode whose spread-rate wind is supplied from outside.

Performance

The lighter back-wall exchange is never used

MESH_EXCHANGE(67) (PACK_WALL_LITE) is never called. Code 66 sends the full PACK_WALL every step (main.f90:1009). This matters for B3 and C3.

Configuration

HYPRE solver settings are compile-time parameters

They are fixed at imkl.f90:204-229. Phase 0.3 addresses this.
